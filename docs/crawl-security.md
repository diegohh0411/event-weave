# Public crawl network safety

Queued/public crawls must construct a `PoliteFetcher` with `validator=validate_public_url` and pass the requested site domain; pass `CrawlSite` objects directly to `crawl` to enable automatic source discovery. Explicit sources, discovered sources, robots requests, redirects, article requests and browser subrequests are checked before transport. Redirected browser requests are fetched one hop at a time; navigation hops also consult robots. JavaScript is disabled in guarded browsers to prevent service workers from bypassing request interception. This may limit extraction on JavaScript-dependent sites.

**DNS rebinding limitation:** validation resolves the hostname and rejects any non-global answer, but HTTPX and Playwright resolve it again for the connection. Addresses are not pinned, so a malicious DNS server can return a public address for validation and a private address for transport. These checks are not a standalone security boundary. Run the crawler with network-level egress rules that deny loopback, private, link-local, cloud metadata and other non-global destinations, including IPv6, or use a transport that pins validated addresses. Do not expose the crawl service to untrusted users without such isolation.
