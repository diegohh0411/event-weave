# 08 · API and web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A FastAPI service (`weave_api`) that exposes adapters, deployments, runs, clusters, documents, enrichment samples, scores and comparisons, and a Nuxt 4 + Nuxt UI app (`web/`) with the six pages from the spec. The app can be built and tested against a mock server that follows the API's OpenAPI schema.

**Architecture:** The API is a thin HTTP layer over code that already exists. It uses `RunService` for runs, the inference `Catalog` for deployments, `weave_eval` for scores and comparisons, and `weave_enrichers.report.sample` for spot checks. New SQL is limited to the read queries for clusters and documents (`weave_api/queries/`). Every run-scoped read goes through `jobs` (`run_id`, `unit_id`), the same way `weave_eval.system` does, because `mentions` and `enrichments` have no `run_id`. The OpenAPI schema is committed as `web/openapi.json`. The web generates its types from that file, and the mock server serves typed fixtures that a Vitest contract test checks against the same file.

**Tech Stack:** Python 3.12, FastAPI, Pydantic 2, SQLAlchemy 2.1, pytest + `fastapi.testclient`. Node 22, pnpm, Nuxt 4, `@nuxt/ui` 4, `openapi-typescript` + `openapi-fetch`, Vitest + `@nuxt/test-utils` + happy-dom, `ajv` (fixture contract test), `h3` (mock server). Pin exact versions when you install them and commit `pnpm-lock.yaml`.

**Spec:** `docs/superpowers/specs/2026-11-05-mvp/08-api-and-web.md` (with `00-overview.md` §3, `01-core.md`; prior plan `2026-11-06-07-evaluation.md`).

## Global Constraints

- Both containers bind to localhost only: `127.0.0.1:8000` (api) and `127.0.0.1:3000` (web). No authentication or login.
- **The web reads data only through the API.** The API never returns gold, except inside score reports (`/runs/{id}/scores`, `/compare`). Only `weave_eval` reads `gold_*` tables. No module in `weave_api` imports `gold_documents`, `gold_mentions` or `gold_pairs`.
- **Every list endpoint pages its results.** Query `offset: int ≥ 0 = 0`, `limit: int 1..200 = 50`. A limit above 200 returns 422. Response `Page[T] = {items: list[T], total: int, offset: int, limit: int}`.
- The API creates runs only through `RunService.create`, built by the same factory the CLI uses (`weave_core.service.build_service`), so the builder and `weave run create` give the same `config_hash`.
- Progress labels shown to users: `pending → queued`, `claimed → running`, `done`, `failed`.
- `RunStateError` → HTTP 409 with `{detail: str}`. `ConfigError` → HTTP 422 with `{problems: list[str]}`. Unknown id → 404.
- Mentions per hour = done jobs of the first stage after `extract` ÷ hours since `started_at` (until `finished_at` once the run has one). Dollars so far = the sum of `ledger.cost` for the run, labelled "estimated" when any row has `estimated`.
- An estimate with no amount is shown as `No estimate yet: <reason>`, never as `$0`.
- The compare view shows paper rows only for Track 1 (`track == "paper"`), labelled `MCECR paper (<model>)`. When `PaperNumbers.checked` is false, the view shows a banner: `Paper numbers UNCHECKED`.
- Document view colours: two mentions get the same colour only when they share a `cluster_id`. A mention with no cluster gets no fill, only a dashed underline.
- No test touches the network or the real dataset. API tests seed Postgres directly (pattern: `packages/clusterer/tests/conftest.py`). Web tests run against fixtures only.

## Review Focus

1. **Gold leaking through a non-score endpoint.** Even an MCECR document page must not reveal gold mention spans or chains. A sweep test seeds gold rows with a marker string and calls every GET route (Task 7).
2. **A run whose cluster jobs failed for some mentions.** The document view shows those mentions as unclustered (no fill), the cluster pages don't list them, and the runs page shows each one's error. Nothing crashes on a `cluster_id` of None (Tasks 3, 5, 13).
3. **An adapter whose capability has no ready deployment.** The picker shows `No ready deployment for <capability>`, Launch is disabled, and a POST anyway returns 422 with the problems (Tasks 2, 3, 9).
4. **A big run** (≈70k mentions, clusters with hundreds of members). Search pages, `limit=500` is rejected, and the members on a cluster page are paged (Tasks 4, 7, 11).
5. **Compare with an unevaluated run, mixed tracks, or Hindi.** An unevaluated run shows `Not evaluated (run weave eval <id>)`, not zeros. Paper rows appear once and only for Track 1. Hindi cross shows the SKIPPED reason (Tasks 6, 12).
