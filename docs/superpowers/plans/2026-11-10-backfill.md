# Step 3 — Backfill

Spec: `docs/superpowers/specs/2026-11-10-library-and-sites-design.md` (delivery step 3).
Branch: `feat/backfill`. Builds on step 2 (#16: `sites`, scheduler tick, `domain_throttle`,
upsert crawls, change reports).

## Outcome

On a site's page you turn on backfill with a start date or "all", and set a pace in
articles per hour. The worker walks the site's sitemap archive and fetches old articles
into the library at that pace, alongside the regular checks. You can pause and resume,
and the page shows progress: sitemaps scanned, URLs found, fetched, stored, the oldest
date reached, and an ETA. Backfill obeys the same per-domain polite limits as checks.

## Decisions for this step

- **Persistent frontier, small jobs.** Backfill state lives in two tables, not in one
  long crawl:
  - `backfill_sitemaps`: archive sitemaps found and whether they have been scanned
  - `backfill_urls`: article URLs found and whether they have been fetched

  The scheduler queues short `crawl_runs` with `trigger='backfill'`. Each job scans at
  most `SCAN_BATCH` (5) pending sitemaps, then fetches at most `FETCH_BATCH` (20) pending
  URLs within the hourly budget, and finishes. Pausing, restarts and lease expiry all
  pick up from the tables, so no job holds the worker for long.
- **Sources.** The roots are the site's configured `sitemaps`. When none are configured,
  the roots are the sitemaps that `resolve_sources` finds through robots.txt. Feeds are
  ignored, since they have no archive.
- **Walking the archive.** Sitemap indexes are walked to depth 3, up to
  `WEAVE_BACKFILL_MAX_SITEMAPS` (default 5000) per site.
  - With a start date, a child sitemap whose index `lastmod` is before the start date is
    recorded as `skipped` and not fetched. Its articles can't be newer than its lastmod.
  - A URL is queued when its publication or lastmod date is between `backfill_from` and
    `backfill_until`.
  - Undated URLs are queued only in "all" mode.
  - URLs not on the site's domain are dropped, using the existing `_on_domain` check.
- **Upper bound.** `backfill_until` is set to `now()` when backfill starts. Anything
  newer belongs to regular checks. An overlap at the boundary is harmless because
  crawls upsert.
- **Order.** Newest first (`published_at desc nulls last`), so the recent past fills in
  first and the oldest date reached keeps moving back.
- **Known URLs.** A URL already in `crawled_pages` is marked `done` with outcome
  `existing` (or its duplicate/rejected status) and is not requested. Backfill never
  re-fetches. Edits are rechecks' job in step 4.
- **Pace.** `backfill_per_hour` (1..1000, default 60) counts backfill page fetches
  (`crawl_articles.fetched = true` in this site's backfill runs) in the last rolling hour,
  measured on DB time.
  - A job fetches at most `min(FETCH_BATCH, per_hour - fetched_last_hour)` URLs.
  - When the budget is used up, the scheduler doesn't queue a new job until it frees.
  - Sitemap fetches don't count toward the pace, but they do go through the polite
    limits.
- **The daily cap ignores backfill.** The step 2 daily cap counts new articles from
  checks only, so its count query excludes `trigger='backfill'` runs. This follows the
  spec: "Backfill has its own hourly pace".
- **Concurrency with checks.** A site may have one active check and one active backfill
  at the same time. `_queue`'s "already active" test becomes per kind: a backfill job
  doesn't block "Check now", and a check doesn't block backfill.
  - `claim_crawl` orders `manual`/`schedule`/`adhoc` before `backfill`, then by
    `created_at`, so new articles never wait behind history. With two worker processes
    both run in parallel.
  - `DomainThrottle` already serializes their requests to the domain.
- **States.** `sites.backfill_state` is one of:
  - `off`
  - `running`
  - `paused`
  - `done`: frontier exhausted
  - `failed`: every root sitemap failed

  Allowed transitions:
  - `start`: from off, done or failed. It resets the frontier when `from` or `mode`
    changed, and otherwise keeps it.
  - `pause`, `resume`, and `cancel`, which returns to `off` and clears the frontier.

  Pausing does not interrupt a job that is already running. The job checks the state
  before each fetch and stops early.
- **Disabling a site** (`enabled=false`) also stops backfill scheduling. It keeps the
  backfill state, so turning the site back on resumes.
- **Backfilled articles are tagged.** `backfill_urls.document_id` plus the run trigger
  are enough for step 4's "recheck backfilled articles" toggle. That toggle is not built
  here.

## Tasks

Each task: TDD, run the touched packages' tests
(`WEAVE_TEST_DATABASE_URL=postgresql+psycopg://weave:weave@127.0.0.1:5432/postgres uv run pytest packages/<p>`,
one package at a time), commit. Containers use **podman** / `podman-compose`, never docker.

### Task 1 — Schema
Migration `0012_backfill` + `weave_core/schema.py`:
- `sites` adds:
  - `backfill_mode text not null default 'off'`, checked to be one of `off`, `date`,
    `all`
  - `backfill_from date null`, required when mode is `date`
  - `backfill_until timestamptz null`
  - `backfill_per_hour int not null default 60`, between 1 and 1000
  - `backfill_state text not null default 'off'`, one of the states above
  - `backfill_started_at`, `backfill_finished_at`, `backfill_error text`
- `backfill_sitemaps`:
  - columns `site_id fk cascade`, `url`, `depth int`, `lastmod timestamptz`, `status`
    (`pending`, `done`, `skipped`, `error`), `error`, `urls_found int default 0`,
    `scanned_at`
  - primary key `(site_id, url)`; index on `(site_id, status)`
- `backfill_urls`:
  - columns `site_id fk cascade`, `canonical_url`, `published_at`, `updated_at`,
    `title`, `sitemap_url`, `status` (`pending`, `done`), `outcome text null` (the
    crawl_articles status), `document_id null`, `crawl_id null`, `done_at`
  - primary key `(site_id, canonical_url)`; index on
    `(site_id, status, published_at desc)`
- `crawl_runs.trigger` check adds `backfill`.
- Tests: up/down on a DB at 0011 with sites and crawls; constraint checks (`date`
  without `from` is rejected, per_hour bounds).

### Task 2 — Archive discovery and frontier (pure + DB, no worker)
- `crawl/backfill.py`:
  - `seed_frontier(engine, site, meta_fetcher)` inserts the root sitemaps as `pending`
    (via robots when none are configured).
  - `scan_sitemaps(engine, site, fetcher, limit, cancelled)` claims up to `limit`
    pending sitemaps with `FOR UPDATE SKIP LOCKED` and fetches and parses each with the
    existing `_sitemap_entries`. It then:
    - inserts child sitemaps, or marks them `skipped` by lastmod or the depth/count cap
    - inserts in-window on-domain URLs with `ON CONFLICT DO NOTHING`
    - sets `urls_found`, `done`/`error`, and `scanned_at`
  - Refactor `discover._sitemap_entries` so index children also return their
    `lastmod`, as `(loc, lastmod)`. Update its callers.
- Tests with `FixtureFetcher`:
  - an index of 3 monthly children, one older than `from`, which is skipped and never
    fetched
  - nested depth handling
  - the count cap
  - off-domain URLs dropped
  - undated URLs kept only in `all` mode
  - a malformed child marked `error` while the others continue
  - rescanning is idempotent

### Task 3 — Fetching frontier URLs through the existing store
- Refactor `store._run_crawl`: move the per-candidate loop into
  `process_candidates(engine, outlet, candidates, fetcher, now, report, emit, …)`.
  `crawl()` keeps calling it after `discover()`, so check behaviour is unchanged.
- Add a `refetch_known: bool = True` parameter. Backfill passes False, so known URLs
  produce `existing`/`duplicate`/`rejected` with no request.
- In `backfill.py`, add `fetch_batch(engine, site, fetcher, limit, now, emit, cancelled,
  write_guard)`. It:
  - claims up to `limit` pending URLs newest first with SKIP LOCKED
  - turns each into a `Candidate`
  - runs them through `process_candidates`
  - marks each `done` with its outcome, document_id and crawl_id, in the same
    transaction as the guard
  - re-reads `backfill_state` before each URL and stops if it is no longer `running`
- `budget_left(conn, site_id)` returns `per_hour` minus the fetches in the last hour.
- Tests:
  - stores new documents
  - known URL gives `existing` and no fetch
  - stops at the budget
  - stops when paused mid-batch
  - a 404 is recorded as an error and not retried in a loop: `done` with outcome
    `error`
  - lease-loss guard is honoured

### Task 4 — Scheduler and worker
- `scheduler.py`:
  - `_queue` gets an active-kind filter: checks look at non-backfill runs, backfill at
    backfill runs.
  - `schedule_due_backfills(engine, now)` uses SKIP LOCKED and bounded batches like
    `schedule_due_sites`. It selects sites that are `enabled`, have `backfill_state =
    'running'`, have no active backfill run, and have budget left or pending sitemaps.
    It inserts `trigger='backfill'` runs with `request` built from the site, `days=1`,
    which the request ignores.
  - The worker tick calls it right after `schedule_due_sites`.
- `jobs.claim_crawl`: order by `(trigger = 'backfill')`, then `created_at` and `id`.
- `worker.process_claim`: for a `backfill` claim, call `seed_frontier` if the frontier
  is empty, then `scan_sitemaps` and `fetch_batch` with the same throttle, guard and
  observer. Then:
  - When nothing is pending in either table, set `state='done'` and
    `backfill_finished_at`.
  - When all roots errored and nothing was found, set `state='failed'` with
    `backfill_error`.
- The daily cap count, in both the pre-claim cap and `consume_cap`, excludes backfill
  runs.
- Tests:
  - a check and a backfill for one site can be active together
  - two backfills can't be
  - a check is claimed before an older backfill
  - paused, disabled and out-of-budget sites are not queued
  - backfill stored articles don't reduce the daily cap
  - state reaches `done`
  - restart resumes from the frontier
  - concurrent ticks queue once

### Task 5 — API
- In `routers/sites.py`:
  - `SiteIn`/`SitePatch`/`SiteOut` gain `backfill_mode`, `backfill_from` and
    `backfill_per_hour`. Validation: `from` is required for `date` and not in the
    future.
  - `POST /sites/{id}/backfill` with body `{action: start|pause|resume|cancel}`. It
    returns 409 on an invalid transition or a disabled site, and 422 when mode is `off`.
    `start` sets `backfill_until=now()` and resets the frontier when mode or from
    changed.
  - `GET /sites/{id}/backfill` returns state, mode, from, until, per_hour, started and
    finished times, and error. It also returns:
    - sitemaps: total, pending, done, skipped, error
    - urls: found, pending, done, plus the stored, existing and rejected/error outcome
      counts
    - `oldest_reached`: min `published_at` of done URLs
    - `fetched_last_hour`
    - `eta`: pending ÷ per_hour, null while sitemaps are still pending
  - `GET /sites` list items gain `backfill_state` and a compact
    `backfill_progress {done, found}`.
- `CrawlOut.trigger` accepts `backfill`. `GET /sites/{id}/crawls` takes an optional
  `trigger` filter, so the history can hide backfill batches by default.
- Regenerate `web/openapi.json` and run `pnpm gen:api`. Tests go in
  `packages/api/tests/test_sites_backfill.py`.

### Task 6 — Web
- `SiteForm.vue`: a "Backfill" section with:
  - a mode radio (Off / From date / Everything), plus the date input
  - per-hour pace, with help text explaining that it counts article fetches and that
    polite limits still apply
  - validation that matches the API
- `pages/sites/[id]/index.vue`: a Backfill card with:
  - a state badge
  - Start / Pause / Resume / Cancel buttons; Cancel asks for confirmation
  - a progress bar of URLs done out of found
  - the counts: sitemaps scanned, stored, already had, rejected
  - "reached back to <date>", "fetching ~N/h", and the ETA, or "still scanning
    sitemaps" while sitemaps are pending

  It polls every 10s while running. The crawl history gets a toggle "show backfill
  batches", off by default.
- `pages/sites/index.vue`: a small backfill column (state plus %).
- `pages/crawls`: trigger badge `backfill`.
- vitest for the progress/ETA formatter and the form validation. `pnpm typecheck` and
  `pnpm build` pass.
