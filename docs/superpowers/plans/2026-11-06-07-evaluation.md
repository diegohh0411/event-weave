# 07 · Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `weave_eval` package and a `weave eval <run>` command. It scores a finished run against MCECR gold: Track 1 within- and cross-document, Track 2 pooled with trigger scores, MUC/B³/CEAF-e/BLANC/CoNLL F1 with bootstrap intervals. It also produces the gold chain check, the cost and speed report and failure counts, stores all of it, and lines it up beside the paper's transcribed numbers.

**Architecture:** Scoring is pure Python over plain dicts: a clustering is `mention key → cluster label`. The database layer only loads gold and the run's clusters into that shape. Every metric is computed from additive `Counts`, the way the reference scorer sums over a corpus. Track 1 scores and its bootstrap are therefore sums of per-document or per-topic `Counts` rows, so 10,000 resamples cost almost nothing. Track 2 is one pooled clustering. Its bootstrap rebuilds the restricted clustering for each resample and runs in a process pool. Results go into two new tables. The paper's numbers live in a versioned YAML file and never enter those tables.

**Tech Stack:** Python 3.12, SQLAlchemy 2.1 + Alembic (core chain), numpy 2.5 and scipy 1.18 (both already in `uv.lock`; scipy for `linear_sum_assignment`), PyYAML, Typer, pytest. The reference CoNLL scorer (Perl, v8.01) is used only offline to produce committed fixture values. CI does not run it.

**Spec:** `docs/superpowers/specs/2026-11-05-mvp/07-evaluation.md` (with `00-overview.md` §3–5, `01-core.md`, `02-inference.md`, `03-document-providers.md`; prior plan `2026-11-06-06-clusterer.md`).

## Global Constraints

- Package `weave-eval` in `packages/eval`, module `weave_eval`, depends on `weave-core`, `numpy`, `scipy`, `pyyaml`, `typer`. It does not import any stage package (`weave_clusterer`, `weave_inference`, …). It reads `ledger`, `jobs` and `cluster_*` through `weave_core.schema`.
- **The scorer is the only reader of gold** in the eval path. Gold tables are read only in `weave_eval.gold`.
- Scores are percentages, 0–100. `conll = mean(muc.f1, b3.f1, ceafe.f1)`. A zero denominator gives 0, never an error.
- Mentions present on only one side are handled as reference scorer v8.01 handles them: no alignment, no removal. A missed gold mention counts against recall and a spurious system mention against precision. Every Track 2 report carries this exact sentence, constant `TRACK2_MENTION_POLICY`:
  `"Mentions present on only one side are kept as the reference CoNLL scorer (v8.01) keeps them: a missed gold mention lowers recall, a spurious system mention lowers precision."`
- Corpus aggregation: Track 1 within-doc = sum of per-document `Counts`; cross-doc = sum of per-topic `Counts`; Track 2 = one clustering. BLANC non-coreference links exist only inside one scored clustering (document, topic, or the pool).
- Topics are keyed `(language, topic)`, because topic ids repeat across languages (PR #3). A topic's split is `gold_documents.split`. `gold_pairs.split` is ignored (it can disagree; PR #3 open item).
- Bootstrap: 95% percentile intervals (2.5th and 97.5th) of F1, `resamples=10_000` by default, resampling topics with replacement within one language. RNG is `numpy.random.default_rng(seed)`, with `seed` = the run config's `seed`. All resample indices are drawn before any parallel work, so the intervals do not depend on how many workers run.
- `SCORER_VERSION = "1"`. Bump it whenever a number could change.
- Refuse any run whose state is not `done`, with the message `run <id> is <state>; only finished runs can be scored`, exit code 1.
- No test touches the network or the real dataset. Tests seed Postgres directly (pattern: `packages/clusterer/tests/conftest.py`).

## Review Focus

1. **Hindi has no cross-doc gold links.** Chain stats must show the mismatch against the paper with the note `"crossDoc pairs unusable in the dataset (no topic or mention ids); chains are within-document only"`. Hindi cross-doc is not scored: no Track 1 cross rows for Hindi, no Hindi documents in Track 2 coreference, and the paper's Hindi cross-doc rows in the compare view show `ours=None` with the `SKIPPED` reason. It must not crash or quietly look comparable. (Task 2, Task 4, Task 6)
2. **A run with failed mentions.** Mentions whose cluster job failed are missing from the response. They count as missed gold (lower recall) and appear in the failure counts beside the score, never dropped from gold. (Task 4, Task 7)
3. **Same topic id in two languages** (for example `1` in English and Spanish). Gold chains, Track 1 partitions and bootstrap units must never merge them. (Task 2, Task 5)
4. **Track 2 duplicates and misalignments.** Two system mentions with the same token span: one matches, the other is spurious. A gold span that is not on token boundaries is counted as `unaligned_gold` and stays in gold as a miss. (Task 4)
5. **Gold pairs that point at an unknown mention, or that cross topics or languages.** These are skipped and counted in `ChainStats.skipped_pairs`, never joined. (Task 2)

### Task 4: Track 1, Track 2 and trigger scores

**Files:** Create `system.py`, `tracks.py`, `tests/test_tracks.py`.

**Interfaces:**
- Consumes: `Gold`, `counts`, `Counts`.
- Produces:
  - `SystemMention(mention_id, document_id, start, end, tok_start, tok_end, cluster_id: str | None)`. `load_system(conn, run_id, document_ids) -> list[SystemMention]` joins `mentions` to `cluster_members` on `run_id`. `cluster_id` is `None` when the mention has no membership (a failed cluster job).
  - `track1(gold, system) -> dict[language, Track1Result]`, `Track1Result(within: dict[(language, topic), Counts], cross: dict[(language, topic), Counts], unmatched_system: int)`. A system mention matches gold by `(document_id, start, end)`. Within: for each document, key = the document's gold mentions, response = the matched system mentions in that document, labelled by `cluster_id`. Each document's `Counts` is summed into its topic row so that the bootstrap unit is the topic. Cross: the same, per topic. A gold mention without a clustered system mention is missing from the response (Review Focus 2).
  - `track2(gold, system) -> Track2Result(per_language: dict[language, Counts], pooled: Counts, inputs: Track2Inputs, unaligned_gold: int)`. Match on `(document_id, tok_start, tok_end)`. Each gold token span takes at most one system mention, the one with the smallest `mention_id`. Unmatched system mentions keep key `("sys", mention_id)`. Unclustered system mentions are left out of the response. Per-language Counts restrict both sides to that language's documents. `Track2Inputs` keeps the key and response dicts plus each key's `(language, topic)` for the bootstrap.
  - `trigger_scores(gold, system) -> dict[language | "all", PRF]` by exact token span, with the same one-to-one matching.
  - `cluster_spread(system, gold) -> Spread(clusters, multi_topic, multi_language)` over clusters that have at least one member in a scored document. A member's topic and language come from its document's `gold_documents` row.
  - `TRACK2_MENTION_POLICY` (the exact text in Global Constraints).

### Task 5: Bootstrap intervals

**Files:** Create `bootstrap.py`, `tests/test_bootstrap.py`.

**Interfaces:**
- Produces:
  - `draw(units: list, resamples: int, seed: int) -> np.ndarray` (shape `resamples × len(units)`, indices). Units are sorted before drawing so the input order does not matter.
  - `interval_additive(rows: dict[unit, Counts], resamples, seed) -> dict[metric, tuple[low, high]]`. It stacks the Counts into a numpy matrix, sums the rows for each resample, and computes F1 vectorised. Used for Track 1, once per language and setting.
  - `interval_pooled(inputs: Track2Inputs, language: str | None, resamples, seed, workers: int = os.cpu_count()) -> dict[metric, tuple[low, high]]`. For each resample it builds the restricted clustering: occurrence `j` of topic `t` adds copies `(key, j)` of t's gold mentions and its matched and spurious system mentions, with response label `(cluster_id, j)`. Copies made by the same occurrence index stay together across topics, and repeated occurrences never merge with each other. Then it calls `counts`. Resamples are split into chunks over a `ProcessPoolExecutor`; the results are put back in resample order. Spurious system mentions belong to their document's topic.

### Task 8: `weave eval`, storage and report

**Files:** Create `evaluate.py`, `store.py`, `render.py`, `cli.py`, `README.md`, `tests/test_evaluate.py`, `tests/test_cli.py`. Modify `packages/core/src/weave_core/cli.py`: mount `eval_command` as `app.command('eval')` behind an `ImportError` guard, the same way as `crawl`.

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `NotFinished(Exception)` with the message from Global Constraints.
  - `evaluate(engine, run_id, *, split="test", resamples=10_000, workers=None) -> Evaluation`. It loads the run and refuses unless the state is `done`. Documents in scope are the run's `extract`-stage document units that have a `gold_documents` row with the given split. If there are none, it refuses with `run <id> has no gold documents in split <split>`. The track comes from `cfg.track`: `paper` → Track 1 (within + cross, per language); `realistic` → Track 2 (pooled per language and `all`, triggers, spread, policy). Every score gets its interval. The result also carries chain stats, cost, failures, `gold_hash`, `config_hash`, `SCORER_VERSION`, `seed` and `resamples`.
  - `Evaluation` (dataclass): `id, run_id, track, split, scores: list[ScoreRow], report: dict`. `ScoreRow` comes from Task 6.
  - `save(engine, evaluation) -> UUID` (one transaction: the `evaluations` row and all score rows). `load_latest(engine, run_id) -> Evaluation | None` (for API 08).
  - `render(evaluation, paper) -> str`. Plain-text tables in this order: scores with CIs; failures; chain stats beside the paper's annotation stats, mismatches marked `≠` with the note; `compare` rows (Track 1); `TRACK2_MENTION_POLICY` (Track 2); `NO_PAIRED_TEST`; cost.
