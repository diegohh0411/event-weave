# 06 · Clusterer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `weave_clusterer` package. It has one `embed`-stage adapter that writes per-field member vectors, and two ordered `cluster`-stage adapters, `system-one` and `threshold`. Each cluster adapter places every enriched mention into an existing cluster or a new one. It uses pgvector retrieval, cluster cards built in code, and a full decision record.

**Architecture:** `embed` is a normal parallel stage (input unit `mention`). It reads the enrichment from `upstream[Stage.enrich]`, embeds each non-empty field twice (document prefix and query prefix) in one request, writes `member_vectors` rows, and forwards the unit. `cluster` runs inside the core ordered writer, one mention at a time per partition. It reads the partition's clusters from `cluster_members` for its own `run_id`, retrieves the top K, asks the decision adapter, and writes the membership, the rebuilt card and the decision record through `StageResult.rows`. The writer commits all of that in one transaction. Cluster outputs depend on partition state, so `cacheable=False`. Replay comes from a `decision_cache` table keyed by the exact request hash. A re-run builds the same requests, hits the cache and makes no calls.

**Tech Stack:** Python 3.12, SQLAlchemy 2.1 + Alembic (core chain), pgvector (extension already created in `0001_core`), Pydantic 2, pytest. No new third-party dependencies: the vector column is a small `UserDefinedType`, and literals are passed as `'[x,y,…]'` text cast to `vector`.

**Spec:** `docs/superpowers/specs/2026-11-05-mvp/06-clusterer.md` (with `00-overview.md`, `01-core.md`, `02-inference.md`, `05-enrichers.md`; prior plan `2026-11-06-05-enrichers.md`).

## Global Constraints

- Package `weave-clusterer` in `packages/clusterer`; depends on `weave-core` and `weave-inference` only. It never imports `weave_enrichers`. It reads enrichments from `upstream[Stage.enrich]["enrichment"]` (the dict shape from spec 05: `action/participants/location/time`, each with `text`, `spans`, `confidence`; `time.normalized`).
- Adapters are registered under entry-point group `weave.adapters`: `embedding-gemma` (stage `embed`), `system-one` and `threshold` (stage `cluster`). All use `input_kind=mention` and version `"1"`. Both cluster adapters have `cacheable=False`.
- Fields, in fixed order: `FIELDS = ("action", "participants", "location", "time")`. A field is empty when `text` is `None` or blank.
- Embedding prefixes for EmbeddingGemma: document `"title: none | text: {value}"`, query `"task: search result | query: {value}"`. They live in the module constant `PREFIXES`, keyed by model id. Checkpoint (deployment id) and `dimension` are embed settings, recorded in the frozen run config. A vector whose length ≠ `dimension` fails the job with `retryable=False`.
- Retrieval stays inside the mention's own `run_id` and partition. Every retrieval query filters on both, and a test enforces it.
- Field score = max cosine similarity over that cluster's member vectors of the same field (member **document** vectors against the new mention's **query** vector). Overall = Σ wᶠ·scoreᶠ / Σ wᶠ over the fields that both sides have. Zero shared fields → score 0.
- `k` must be ≥1, and the value actually used is `min(k, deployment.limits.max_choice_options)` when that limit is set. Settings: `k: int`, `weights: dict[field, float]` (all four, ≥0, sum >0), `threshold: float` in `0..1` (Noul cutoff for System One, retrieval-score cutoff for the threshold adapter), `card_values_per_field: int = 3`, `card_max_chars: int = 600`. `threshold` and `k` have no defaults: they are tuned on English dev and recorded in the run config.
- Model requests contain only the mention's marked sentence, its fields, its document title and `published_at`, plus cards under labels `c1…cK`. No cluster id, document id, topic, split, partition name or gold value. A test serialises every ledgered request and checks none of these appear.
- Nothing about a cluster is model-written. A card is a pure function of its member rows, so rebuilding it from the same members gives the same card and the same `card_hash`.
- No test touches the network. Models come from the stub provider (scripted embeddings and answers), and tests use the real Postgres from the core plan.

## Review Focus

1. **A mention with all four fields empty** (an enricher found nothing): no vectors, no retrieval possible. It must start a new singleton cluster with no decision call and a record saying `outcome="new", reason="no_fields"`. It must not fail. (Task 4)
2. **Two mentions of the same document arrive back to back**: the second must see the first's cluster. Membership written by job N must be visible to job N+1 in the same writer session. (Task 4)
3. **The System One Noul passes but the Choice points at a label that wasn't offered** (stub or provider bug): treat it as `new` with `reason="invalid_choice"`, counted. Never an index error, never a random join. (Task 5)
4. **Fewer clusters than K in the partition**: the Choice gets only the clusters that exist. One candidate → no Choice, Noul only, and a join picks that one. (Task 5)
5. **Card ties** (two members with equal average similarity, or equal value frequency): break them by `(order_key, mention_id)` so the card is deterministic. (Task 3)

### Task 3: Retrieval and cluster cards

**Files:** Create `state.py`, `retrieval.py`, `cards.py`, `tests/test_retrieval.py`, `tests/test_cards.py`.

**Interfaces:**
- Produces:
  - `PartitionView(session, run_id, partition)`: `.cluster_ids() -> list[str]`, `.members(cluster_id) -> list[Member]`. `Member(mention_id, order_key, enrichment: dict, sentence: str, language: str, published_at: datetime | None, vectors: dict[field, list[float]])` (document vectors only). Joins `cluster_members → mentions → documents`, `member_vectors`, and the run's `enrich` stage outputs (stage outputs are run-scoped, so an earlier run's enrichment cannot leak in).
  - `retrieve(session, run_id, partition, query: dict[field, vector_literal], weights, k) -> list[Candidate]`. `Candidate(cluster_id, score, field_scores: dict[field, float])`, sorted by `(-score, cluster_id)`. One SQL query per present field: `max(1 - (mv.vector <=> :q))` grouped by `cluster_id` over `cluster_members cm JOIN member_vectors mv ON mv.mention_id = cm.mention_id AND mv.field = :f AND mv.kind = 'document' WHERE cm.run_id = :run AND cm.partition = :p`. Combining scores happens in Python with renormalised weights.
  - `build_card(members: list[Member], values_per_field: int, max_chars: int) -> Card`. Representative = highest mean cosine over the other members' vectors, averaged across shared fields (a lone member is its own representative). Ties go to the smaller `(order_key, mention_id)`. Per field: the representative's value first, then the other distinct values by frequency desc, ties by first `order_key`, up to `values_per_field`. Also `size`, sorted `languages`, `earliest`, `latest`, and `sentence` (the representative's). Truncation: drop trailing values per field, then cut `sentence` with `…`, until `len(card.render()) ≤ max_chars`.
  - `Card.render() -> str` (the exact text shown to the model, with no ids) and `card_hash(card) -> str` = sha256 of the canonical JSON.

### Task 4: Clusterer base and threshold adapter

**Files:** Create `base.py`, `threshold.py`, `tests/test_threshold.py`, `tests/test_writer_flow.py`.

**Interfaces:**
- Consumes: Tasks 1–3; core `run_writer`, `StageResult.rows`.
- Produces:
  - `ClustererBase.process(unit, upstream, partition, session)`: loads its own query vectors (`kind='query'`) for `unit.id`. If there are no vectors → new cluster, `reason="no_fields"`. If the partition has no clusters → new cluster, `reason="empty_partition"`, no call. Otherwise it runs `retrieve(..., k=self.effective_k())` and then `self.decide(mention_ctx, candidates, cards) -> Decision(outcome, cluster_id | None, reason, noul, probabilities, deployment)`. Then it rebuilds the target cluster's card from members + this mention, and returns rows for `clusters` (upsert), `cluster_members` and `cluster_decisions`. Output `{"cluster_id", "outcome"}`, `emits=None` (end of pipeline). It needs `run_id` from the `AdapterContext`; check that the cluster adapter's context carries it, and add it there if not.
  - `ClustererBase.effective_k() -> int`.
  - `ThresholdClusterer`: `capabilities=frozenset()`. Join `candidates[0]` iff `score ≥ threshold`, else new with `reason="below_threshold"`.

### Task 5: System One decision adapter and decision cache

**Files:** Create `system_one.py`, `decisions.py`, `tests/test_system_one.py`.

**Interfaces:**
- Consumes: `Inference.system_one`, `Inference.deployment(Capability.system_one)`, `check_limits`, `LimitExceeded`.
- Produces:
  - `build_request(mention_ctx, cards: list[Card]) -> SystemOneRequest`. State is the text `Title: …\nPublished: …\nSentence: …⟦trigger⟧…\nAction/Participants/Location/Time: …` (omitted lines when absent), then `Candidates:` with one `c{i}: {card.render()}` block per card. Questions: `Noul(id="same", prompt="Does any candidate describe the same real-world event as the mention?")` and `Choice(id="which", prompt="Which candidate describes the same real-world event?", options=["c1",…])`. Leave the Choice out when there is only one card.
  - Context fit: call `check_limits(deployment, request)`. On `LimitExceeded("context"…)`, rebuild the cards with `values_per_field - 1` (down to 1), then halve `max_chars`. If it still doesn't fit, drop the lowest-scored candidate and record `reason` suffix `"+trimmed"`. A request is never sent over the limit.
  - `cached_system_one(inference, session, request) -> SystemOneResponse`: key = `sha256(deployment, request canonical JSON)`. On a hit, return the stored response with no call and no ledger row. On a miss, call and insert.
  - `SystemOneClusterer`: `capabilities={system_one}`. Join when `noul ≥ threshold` and the chosen label is valid (single-candidate case: that candidate). Otherwise new, with `reason` in `{"noul_below_threshold", "invalid_choice"}`. The record stores `probabilities` (Choice) and `noul`.

### Task 6: Report, recall@K and end-to-end check

**Files:** Create `report.py`, `cli.py`, `tests/test_report.py`, `tests/test_pipeline.py`; mount the `clusterer` Typer group in `weave_core/cli.py` the same way as `enrichers`.

**Interfaces:**
- Produces:
  - `summary(engine, run_id) -> Summary(mentions, clustered, failed, clusters, singletons, decision_calls, outcomes: dict[reason, int])`.
  - `recall_at_k(engine, run_id, k: int | None = None) -> RecallRow(language, mentions_with_gold_antecedent, hits, recall)`. It is evaluation-only code, so it may read gold. Gold mention identity is matched by `(document_id, start, end)` against `gold_mentions`. For each mention that has an earlier gold-coreferent mention in its partition, a hit means one of those mentions' clusters is among the recorded candidates in `cluster_decisions`. `k` < recorded K re-slices the stored candidates, so sweeping K needs no re-run.
  - `weave clusterer report <run> [--k N]` prints both.
  - Tuning (K, weights, thresholds by CoNLL F1 on English dev) needs the scorer from spec 07, so it is not built here. Document the procedure in the package README: grid runs with `threshold` first (no model cost), then System One at the chosen K.
