# Step 4 — Rechecks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-fetch every stored article about 1, 7 and 30 days after it was first fetched. Record each outcome (unchanged, edited, gone or redirected away), and show edited and removed documents in the library with badges and filters.

**Architecture:** Recheck schedule state is stored on `crawled_pages` (stage, due time, attempts), and each attempt is logged in a new `page_rechecks` table. The scheduler tick queues short `crawl_runs` with `trigger='recheck'` for sites that have due pages. The worker claims them after checks and before backfill, and re-fetches up to `RECHECK_BATCH` pages through the same `PoliteFetcher` + `DomainThrottle`. It reuses step 2's `_refetch` versioning, extended with redirect classification.

**Tech Stack:** Python 3 / SQLAlchemy Core / Alembic / Postgres, FastAPI, Nuxt 4 + Nuxt UI, vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-library-and-sites-design.md` (goal 7, delivery step 4, "Calls made by the designer: Redirects"). Builds on step 2 (#16: `_refetch`, versions, `crawled_pages.status='gone'`) and step 3 (#17: `backfill_urls`, per-kind `_queue`, claim ordering).

Branch: `feat/rechecks`.

## Global Constraints

- Schedule ≈ **1 / 7 / 30 days after first fetch**, then never again. The intervals are a setting: env `WEAVE_RECHECK_DAYS`, default `1,7,30`, comma-separated positive integers in ascending order. An invalid value fails worker startup.
- Applies to backfilled articles too. A per-site toggle, **"Recheck backfilled articles"** (`sites.recheck_backfilled`, default `true`), opts them out.
- Outcomes: `unchanged` / `edited` (new version) / `gone` (404/410) / `redirected` (redirected away). Transient failures are `error`.
- A new version is created only when the normalized title or body changes (the existing `edit_hash`). Byline or publish-date changes update the document in place.
- A redirect to the homepage, a section page or another domain counts as **removed**. A redirect to another article URL on the same site keeps the document: its URL is updated, and a new version is created only if the text changed.
- Rechecks are bounded only by the per-domain polite limits. They never bypass `PoliteFetcher`/`DomainThrottle`, and they don't count toward the daily cap or the backfill pace.
- Scheduler priority: new articles, then rechecks, then backfill.
- Runs still include edited and removed documents by default. Excluding them is a filter the user chooses.
- A URL dropping out of a sitemap is **not** a removal.
- Never overwrite a version a run used. Edits always insert a new version row.
- Containers use **podman** / `podman-compose`, never docker.
- Test command, one package at a time: `WEAVE_TEST_DATABASE_URL=postgresql+psycopg://weave:weave@127.0.0.1:55439/postgres uv run pytest packages/<p>`

## Review Focus

1. **Off-domain redirect vs. robots block.** Today `PoliteFetcher` returns `"robots disallowed"` for both. If a robots block is read as "redirected away", documents get marked removed wrongly. Expected: only a real 3xx chain ending off-domain counts as `redirected`, and a robots block counts as `error`. (Task 2 test `test_offsite_redirect_distinct_from_robots`.)
2. **Site down for a day (5xx / timeouts).** Expected: no false "removed". The page is retried after `RETRY_HOURS` (6), and after `MAX_ATTEMPTS` (3) the stage is recorded as `error` and the schedule advances. (Task 3 test `test_transient_error_retries_then_advances`.)
3. **Slug change onto a URL that is already a different document.** Expected: no merge and no lost document. The recheck records `redirected` with reason `"redirect to known document <id>"` and marks the page gone. (Task 3 test `test_slug_change_onto_known_url_marks_removed`.)
4. **Toggle "recheck backfilled" off with rechecks already queued.** Expected: pages queued before the toggle may finish, and no new backfilled pages are picked after it. Toggling back on resumes from their stored stage. (Task 4 test `test_backfill_toggle_is_dynamic`.)
5. **Gone page that comes back.** A page that is `gone` stays gone: rechecks stop and later checks don't resurrect it, which matches today's behavior. Expected: the library still shows the "removed" badge, and the document stays readable and selectable by runs. (Task 5 test `test_removed_documents_listed_by_default`.)

### Task 3: Recheck one page

**Files:**
- Create: `packages/providers/src/weave_providers/crawl/recheck.py`
- Modify: `packages/providers/src/weave_providers/crawl/store.py`:
  - extract the text-version logic of `_refetch` (lines 270–289) into `apply_text(conn, candidate, result, raw, now, doc_id) -> tuple[str, str]`, which returns `("unchanged"|"updated", current_doc_id)`, so `_refetch` and recheck share it
  - `_crawl_page` sets `first_fetched_at=now` and stage 0 with its due time on insert
- Test: `packages/providers/tests/test_recheck.py`

**Interfaces:**
- Consumes: `REDIRECTED_AWAY` (Task 2), `extract`, `edit_hash`, and the `_upsert_page` and `apply_text` helpers in `store.py`.
- Produces:
  - `recheck_days() -> list[int]`: parses `WEAVE_RECHECK_DAYS`, raising `ValueError` on bad input
  - `next_due(first_fetched_at, stage, days) -> datetime | None`
  - `RETRY_HOURS = 6`, `MAX_ATTEMPTS = 3`
  - `recheck_page(engine, page, fetcher, now, days, crawl_id, write_guard, cancelled) -> dict | None`. Here `page` is a `crawled_pages` row mapping. It returns the `crawl_articles` outcome dict (`status` is one of `unchanged`, `updated`, `removed`, `redirected`, `error`, plus `document_id`, `reason` and `fetched`), or `None` when cancelled. In one guarded transaction it writes a `page_rechecks` row and advances `crawled_pages`.

Classification, in order:

| Fetch result | Outcome | `crawled_pages` effect |
|---|---|---|
| status 404 / 410 | `gone` (article status `removed`) | `status='gone'`, `gone_at=now`, `gone_reason='HTTP 404'`, due → null |
| `error == REDIRECTED_AWAY` | `redirected` | gone, `gone_reason='redirected to <final>'`, due → null |
| 200, `final_url` path is `/` or `extract` → `Rejected` after a redirect | `redirected` | gone, `gone_reason='redirected to <final>'` |
| 200, same-site `final_url` already in `crawled_pages` for a different document | `redirected` | gone, `reason='redirect to known document <id>'` |
| 200, same-site `final_url` new and extractable (slug change) | `unchanged` or `edited` via `apply_text` | update `url=final` on the page and on the current document version, if unchanged in place; upsert a `crawled_pages` row for `canonical_url(final)` → same doc with `recheck_due_at = null` |
| 200, no redirect, extractable | `unchanged` / `edited` | stage + 1, due = `next_due(...)` |
| 200, no redirect, `Rejected` | `unchanged` with reason `refetch rejected: …` (matches `_refetch`) | stage + 1 |
| 5xx / status 0 / network / robots | `error` | attempts + 1, due = now + 6h. On the 3rd attempt: log `error`, stage + 1, attempts → 0 |
