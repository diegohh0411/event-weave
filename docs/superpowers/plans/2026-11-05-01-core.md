# 01 · Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The skeleton every later spec plugs into: a uv workspace, Postgres schema and migrations, frozen run configurations, a stage adapter contract with a registry, a Postgres job queue with cached outputs, an ordered writer for clustering, the `weave` CLI, and a compose file.

**Architecture:** One `weave_core` package owns the schema, the run lifecycle, the queue, the cache and the ordered writer, and knows nothing about any concrete stage. Stage packages (specs 03–06) register adapters through the `weave.adapters` entry-point group. Work flows as jobs: the provider job emits document units, each completed job emits the units for the next stage, and the clustering stage is drained by one writer per partition under a Postgres advisory lock.

**Tech Stack:** Python 3.12, uv workspaces, SQLAlchemy 2.1 (sync) + psycopg 3, Alembic, Pydantic 2, Typer, FastAPI + Uvicorn (health endpoint only), pytest, Postgres 17 with pgvector, podman compose.

**Spec:** `docs/superpowers/specs/2026-11-05-mvp/01-core.md` (and the overview, `00-overview.md`).

## Global Constraints

- Python `>=3.12,<3.13`; one uv workspace; a stage package depends on `weave_core` (and later `weave_inference`), never on another stage package.
- Services bind to `127.0.0.1` only. Secrets live in a git-ignored `.env`; `.env.example` documents every variable.
- llama.cpp is **not** a compose service; containers reach the host at `host.containers.internal`.
- Retry policy: 3 attempts, exponential backoff; then the job is `failed` with its error and the run continues.
- A job whose worker stops heartbeating is released. Heartbeat every 10 s; stale after 60 s.
- Tracks are `paper` (one partition per topic) and `realistic` (one partition for the whole run).
- Configuration is validated and hashed at creation and frozen at start.
- No stage adapter receives gold, other runs' data or another partition's data.
- Tests use a real Postgres: `podman run -d --rm --name weave-test-pg -e POSTGRES_USER=weave -e POSTGRES_PASSWORD=weave -p 127.0.0.1:5432:5432 docker.io/pgvector/pgvector:pg17`, then wait on `podman exec weave-test-pg pg_isready -U weave`.

**Scope decision (this plan):** compose gets `postgres`, `api` (health and migrations only) and the stage workers. The `web`, `crawler` and `stanza` services are added by specs 08, 03 and 04, which own their images. Gold tables are added by spec 03's migration.

## Approved corrections (Diego, 2026-11-05)

Task 4 incorporates these approved corrections to Tasks 3–6 without rewriting prior task commits. `Queue(engine)` is unchanged; completion requires the executed `AdapterSpec`, validates stage/name, and records its adapter/version. The initial provide unit's `content_hash` and job `input_hash` hash only the normalized provider `StageChoice` (JSON mode, sorted keys, compact separators, including filled defaults); the whole-run configuration and `config_hash` are unchanged. Child hashes retain the uniform chaining rule below. Clusterer-only changes therefore preserve provider hashes, while provider-settings changes invalidate them.

**Version-pinning checkpoint:** decide run version pinning before spec 03/04 real adapters merge. This task records executed versions; it does not pin versions per run. The compose service deferral above remains approved.

## Review Focus

1. A worker dies after writing its output but before marking the job done: the job is redone, and no duplicate output or downstream job appears. (Task 4)
2. Two clustering workers start on the same run: only one ever processes a given partition. (Task 7)
3. An adapter's `version` is bumped with everything else unchanged: the cache misses and the adapter runs again; it never reuses the old output. (Task 5)
4. The same configuration written once with defaults omitted and once with defaults spelled out gets the same hash. (Task 2)
5. A provider emits the same document twice, or a `paper` run gets a document with no topic: one document and one job, or a job failure that names the problem. (Task 6)

**Files:**

**Interfaces:**
- Consumes: `validate`, `config_hash`, `RunConfig` (Task 2); `session_scope`, tables (Task 1).
- Produces:
  - `Protocol CostEstimator`: `estimate(cfg: RunConfig) -> Decimal | None`. Default `NoEstimate` returns `None`. Spec 02 supplies the real one.
  - `@dataclass RunCreated(run_id: UUID, config_hash: str, estimate: Decimal | None)`
  - `@dataclass RunStatus(state: RunState, stages: dict[Stage, dict[JobStatus, int]])`
  - `class RunService(engine, registry, catalog, estimator: CostEstimator = NoEstimate())` with `create(cfg) -> RunCreated`, `start(run_id)`, `cancel(run_id)`, `resume(run_id)`, `status(run_id) -> RunStatus`.
  - Module function `mark_done_if_finished(session, run_id: UUID) -> bool` (used by the queue and the writer).
  - `class RunStateError(Exception)` for illegal transitions.
- Behaviour:
  - `create` validates (raising `ConfigError`), stores the validated config and its hash, state `created`.
  - `start` (only from `created`) sets `running` and enqueues exactly one `provide` job: unit `UnitRef(kind=run, id=str(run_id), content_hash=provider_hash)`, partition `"*"`, order key `()`. Both `provider_hash` and the job's initial `input_hash` are SHA256 hex of `json.dumps(validated_cfg.stages[Stage.provide].model_dump(mode="json"), sort_keys=True, separators=(",", ":"))`. This approved correction is implemented in Task 4; whole-run `config_hash` stays unchanged.
  - `cancel` (only from `running`) sets `cancelled`. Workers stop claiming its jobs; jobs already claimed may finish.
  - `resume` (only from `cancelled`) sets `running`; nothing is re-enqueued.
  - `mark_done_if_finished` sets `done` when the run has no `pending` or `claimed` jobs.

**Files:**

**Interfaces:**
- Consumes: tables (Task 1); `Stage`, `JobStatus`, `UnitRef`, `StageResult`, `AdapterFailure`, `AdapterSpec` (Task 2); `runs.mark_done_if_finished` (Task 3).
- Produces (`pipeline.py`):
  - `next_stage(cfg: RunConfig, stage: Stage) -> Stage | None`: the next stage in `PIPELINE` that the config has (skips an absent `tag`).
  - `child_units(parent: ClaimedJob, result: StageResult) -> list[UnitRef]`: `emits` or `[parent.unit]` when `emits is None`. Units emitted by any stage except `provide` get `order_key = parent.order_key + (i,)` in emission order; `provide` units keep their own order key.
  - `child_partition(track: Track, parent_partition: str, unit: UnitRef) -> str`: for `realistic`, `"all"`; for `paper`, the unit's `partition_hint` when the parent is the provide job (`"*"`), otherwise the parent's partition. A `paper` document unit with no hint raises `AdapterFailure("paper track needs a topic for document '{id}'", retryable=False)`.
- Produces (`queue.py`): constants `MAX_ATTEMPTS = 3`, `BACKOFF_BASE = timedelta(seconds=2)` (delay `BACKOFF_BASE * 2**(attempts-1)`), `STALE_AFTER = timedelta(seconds=60)`, `HEARTBEAT_EVERY = timedelta(seconds=10)`.
  - `@dataclass ClaimedJob(id, run_id, stage, unit: UnitRef, partition, order_key: tuple[int, ...], input_hash, attempts, claim_token: UUID, parent_job_id: int | None)`
  - `class Queue(engine)`:
    - `claim(stage: Stage, limit: int, worker_id: str, now: datetime | None = None) -> list[ClaimedJob]`: `pending` jobs of `running` runs with `available_at <= now()`, oldest first, `FOR UPDATE SKIP LOCKED`; sets `claimed`, `claimed_by`, a new `claim_token`, `heartbeat_at`.
    - `complete(job: ClaimedJob, result: StageResult, cache_key: str | None, *, spec: AdapterSpec) -> bool`: in one transaction, only if the row is still `claimed` with the same `claim_token`: upsert documents (`ON CONFLICT DO NOTHING`), store the output (`stage_outputs`, `ON CONFLICT DO NOTHING` when `cache_key` is set), set `done` and `cache_key`, insert child jobs for `next_stage` (`ON CONFLICT (run_id, stage, unit_id) DO NOTHING`), then `runs.mark_done_if_finished`. Returns `False` if the claim was lost (nothing written). Approved correction: reject `spec.stage != job.stage` with `ValueError` before writes; after the valid claim-token guard and frozen-config read, reject a spec name different from the configured stage adapter with `ValueError` and roll back all writes. When `cache_key` is set, store `stage=job.stage`, `adapter=spec.name`, `adapter_version=spec.version` from the same executed spec used for the cache key. With no key, store no output row; spec remains required.
    - `fail(job: ClaimedJob, failure: AdapterFailure) -> None`: increments `attempts`; if `retryable` and `attempts < MAX_ATTEMPTS`, back to `pending` with the backoff delay; else `failed` with `error = failure.reason`; then `mark_done_if_finished`.
    - `heartbeat(worker_id: str, now: datetime | None = None) -> None`; `release_stale(now: datetime | None = None) -> int`: jobs `claimed` with `heartbeat_at < now - STALE_AFTER` go back to `pending` with `claim_token` cleared, `attempts` incremented.
    - `upstream(job: ClaimedJob) -> dict[Stage, dict]`: outputs of the job's ancestors, walking `parent_job_id` and reading `stage_outputs` by `cache_key`.
  - A child job's `input_hash = sha256(unit.content_hash + ":" + (parent cache_key or ""))`.

### Task 7: Partitions and the ordered writer

**Files:**
- Create: `packages/core/src/weave_core/writer.py`
- Modify: `packages/core/tests/fakes.py` (`fake-cluster`)
- Test: `packages/core/tests/test_writer.py`

**Interfaces:**
- Consumes: `Queue` (Task 4), `OrderedStageAdapter` (Task 2), `run_worker`'s adapter construction (Task 6; factor it into `worker.build_adapter(session, run_id, stage, registry)` and reuse it).
- Produces:
  - `partition_lock_key(run_id: UUID, stage: Stage, partition: str) -> int`: the first 8 bytes of sha256(`f"{run_id}:{stage}:{partition}"`) as a signed 64-bit int.
  - `next_job(session, run_id, stage, partition) -> ClaimedJob | Blocked | None`: the `pending` job of `(run, stage, partition)` with the smallest `order_key`. It is `Blocked` while any job of an **earlier** stage in the same run, in this partition or in partition `"*"`, is `pending` or `claimed` with `order_key <= ` that job's key. Postgres array comparison gives the right order: `[r] < [r, p]` and `[] <` everything.
  - `run_writer(engine, registry, stage: Stage, worker_id: str, *, threads: int = 4, poll_interval: float = 1.0, stop: threading.Event, once: bool = False) -> None`. Refuses non-ordered stages. Each thread loops: pick a `(run, partition)` of a `running` run that has pending jobs of `stage`, take `pg_try_advisory_lock(partition_lock_key(...))` on a dedicated connection (skip the partition if not acquired), then repeatedly take `next_job` and, in one transaction, call `adapter.process(unit, upstream, partition, session)` and mark the job `done`. On `Blocked` or `None`, release the lock and move on. Failures retry in place up to `MAX_ATTEMPTS` with backoff (never skipping ahead), then the job is `failed` and the writer continues with the next job. After each job, `mark_done_if_finished`.
- If Task 7 shares completion logic, preserve the required executed `spec` argument and stage/name validation, while keeping adapter writes and job completion in the same writer transaction. Do not call a separately committing `Queue.complete` from that transaction.
- `fake-cluster` appends `(partition, unit.id)` to a table `fake_cluster_log` created by the test fixture, and assigns cluster `hash(unit.id) % 3`, written in the given session.
